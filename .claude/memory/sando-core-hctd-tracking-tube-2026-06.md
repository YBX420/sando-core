2026-06-26: implemented the HCT-D tracking tube so the maneuver mover certificate covers the FLOWN path (not just the planned B-spline), closing the project's "tracking-error eats the margin" gap.

**What.** `MAN_TRACK` in `metaurban/render_3d_video.py` default 0.0 → **0.29** (a real calibrated value, was placeholder). Added to BOTH the horizontal mover keep-out (`cert_R = r_obs + MAN_DSAFE + MAN_QCONF + MAN_TRACK`) and the vertical fly-over `z_clear` (the seed-56 truck collision was a VERTICAL graze, so vertical mattered). `EGO_TRACK=0` disables.

**Calibration (model-free, split-conformal).** Harvested 99 real-quad episodes (seeds 0-99, `--maneuver --headless` + `TRACK_HARVEST=1` → `metaurban/out/conformal/track/track_s*.npy`, rows = (window, δ=‖p_flown−p_planned‖, ‖v‖, ‖a‖, lateral)). `metaurban/track_conformal.py` now emits a deployable **per-commit-WINDOW** δ_track (the cert re-certifies each commit, so the window is the exchangeable unit — NOT the per-episode block, whose κ explodes to 51 from one switch-blowup per episode). eps0.01 → δ_track=0.291m, held-out window coverage 0.996. Output `out/conformal/track_calib.json`.

**Data finding.** Tracking is near-perfect 99% of commits (per-substep δ median 3mm, p99 0.10m); heavy tail to 2.9m is only 0.57% of substeps = maneuver-switch / re-plan path JUMPS (fast drone momentarily off a freshly-jumped committed path). δ correlates with ‖a‖/curvature (+0.24/+0.22) NOT speed (−0.05) — confirms the HCT-D thesis. The tail is left to commit-hysteresis (precondition), not covered by a reach-killing static margin.

**Result (100-scene benchmark, real quad dynamics, crash=stop).** ours went from {撞人0 撞车1 撞动物0 坠机6, reach 92} → **{撞人0 撞车0 撞动物0 坠机6, reach 93}**. ALL moving-obstacle collisions now 0 (mover 1→0; the closed one = seed 56, an 8.3 m/s truck, −0.118→+0.089). Net total collisions 7→6, reach 92→93. Residual 6 are static grazes (EGO self-avoidance / static gate, separate from the mover cert). vs native EGO 70 reach, 2/6/2/19. See [[sando-core-status-2026-06]]; full writeup `docs/algorithm-comparisons-2026-06.md` §2.

**Caveat.** Adding the mover margin re-routes paths, which fixed 2 static grazes (seed 30/45) but caused 2 new small ones (seed 6 −0.015 / 58 −0.091) — mover-margin and static are coupled. δ_track is sim-calibrated (MetaUrban quad model), needs per-drone recalibration on hardware.

**★★ CODE-REVIEW CORRECTION (2026-06-27, 6-dim multi-agent review + adversarial verify; `docs/code-review-2026-06-27.md`).** The review (26/34 findings confirmed real, re-ran data) caught that my δ_track was UNSOUND: I used the per-commit-WINDOW as the conformal exchangeable unit, but windows within a flight are autocorrelated → not exchangeable. The honest unit is the EPISODE (per-flight). At the deployed 0.29m, **30% of flights actually breached** (per-flight coverage ~70%, not the claimed 99%). ROOT CAUSE of the huge honest margin = maneuver-switch THRASHING (MAN_DEADBAND hysteresis was DEAD CODE, never read). FIXES applied: (1) **climb/over fallback now requires the cert; if nothing certifies → HOLD (brake/hover)**, never fly uncertified (was a soundness hole); (2) **commit hysteresis made live** (straight-first, then previous side before its mirror) → per-episode-max δ p95 collapsed 1.72→0.27m; (3) **δ_track recalibrated per-flight** → MAN_TRACK 0.29→**0.45** (eps0.05=0.264, max obs 0.473); (4) **DNF (stuck/timeout) now explicit** in render_screen (counted as failure, not silently dropped); track_conformal.py emits per-flight delta_track_m + per-window as reference-only.
